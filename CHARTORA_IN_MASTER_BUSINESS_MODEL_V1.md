## 3. FUNCTIONS, OPERATIONS & CUSTOMER JOURNEY

### 3.1 Core 10-Step Product Workflow
Chartora structures the entire trading decision lifecycle into ten distinct operational steps:
1. **SCAN**: Automated multi-timeframe algorithm monitoring technical conditions.
2. **IDENTIFY**: Setup detection (e.g. 5M/15M 9/21 EMA pullback, structure break).
3. **VALIDATE**: Confluence verification against higher timeframe market trend.
4. **ALERT**: Instant delivery via website notification and Telegram channel.
5. **PLAN**: Position sizing, Stop Loss, and Take Profit target calculation.
6. **ENTER**: Independent trade execution by the trader on their brokerage.
7. **MANAGE**: Trade tracking (TP1, TP2, TP3, Breakeven, SL).
8. **EXIT**: Setup outcome recording and trade closure.
9. **REVIEW**: Post-trade logging in the Chartora Trade Journal.
10. **LEARN**: Educational feedback loop reinforcing strategy concepts in the Academy.

### 3.2 Customer Onboarding Journey
1. **Discovery**: Visitor arrives via organic social media (YouTube, X, Instagram Reels).
2. **Public Website**: Reviews features, market coverage, and free Academy chapters on `https://chartora.in`.
3. **Free Public Telegram**: Joins public Telegram channel (`https://t.me/chartora_official`) for daily recaps and educational previews.
4. **Subscription Checkout**: Selects plan and completes payment via Stripe Checkout.
5. **Instant Entitlement Activation**: Server receives verified Stripe webhook, creates user session, and grants plan entitlements.
6. **Member Command Center**: User logs into `https://app.chartora.in` (`/#dashboard`).
7. **Telegram Access**: Requests single-use expiring invite link to join private setup alert channels.
8. **Ongoing Membership**: Enjoys market updates, Academy courses, performance engine logs, and community discussions.

## 4. CONTROLLED TELEGRAM ACCESS & SECURITY ARCHITECTURE

### 4.1 Channel Structure
- **Public Channel** (`https://t.me/chartora_official`): Open to everyone. Used for announcements, educational recaps, and lead conversion.
- **Private Premium Channels**: Accessible strictly to active paid subscribers.

### 4.2 Security Protocol: Single-Use Expiring Invites
To prevent permanent invite link leaks, Chartora uses an automated Telegram Bot API service:
- Invites are generated dynamically on demand (`/api/telegram/request-invite`).
- **Single Use**: `member_limit: 1`.
- **Expiring**: `expire_date: +3 days` (259,200 seconds).
- Permanent invite URLs are **never** stored or displayed publicly.

### 4.3 Automated Revocation Queue
When a user's subscription changes to `CANCELLED`, `EXPIRED`, or `UNPAID`:
1. Server updates subscription state in `subscriptions` table.
2. User's Telegram entitlement is immediately revoked.
3. System executes Telegram Bot API `banChatMember` followed by `unbanChatMember` to cleanly remove the user from the private channel while allowing re-entry if they resubscribe later.

## 5. VIRTUAL SETUP PERFORMANCE ENGINE

### 5.1 Deterministic Calculation Engine
Chartora tracks published technical setups to provide transparent historical analytics. Performance metrics are calculated deterministically:

- **BUY Setup Math**:
  $$\text{Risk} = \text{Entry} - \text{SL} \qquad \text{Reward} = \text{Exit} - \text{Entry} \qquad R = \frac{\text{Reward}}{\text{Risk}}$$
- **SELL Setup Math**:
  $$\text{Risk} = \text{SL} - \text{Entry} \qquad \text{Reward} = \text{Entry} - \text{Exit} \qquad R = \frac{\text{Reward}}{\text{Risk}}$$

### 5.2 Metrics Tracked
- **Total Published Setups**
- **Win Rate (%)**: $\frac{\text{Winners}}{\text{Total Setups}} \times 100$
- **Cumulative Virtual R**: Sum of all setup $R$-multiples.
- **Profit Factor**: $\frac{\text{Gross Virtual Gains}}{\text{Gross Virtual Losses}}$
- **Max Virtual Drawdown (R)**

### 5.3 Mandatory Analytical Disclaimer
All performance views prominently display the required disclaimer:
> *⚠️ Virtual/educational performance based strictly on published Chartora technical setups. This does not represent actual client brokerage returns or guaranteed profits.*

## 8. TECHNICAL STACK SETUP & INFRASTRUCTURE

### 8.1 Core Technology Stack
- **Frontend**: HTML5, CSS3 (Vanilla CSS with custom properties), Client-side SPA Router (`js/app.js`), Three.js 3D WebGL Canvas.
- **Server Engine**: Node.js / Python 3 Full-Stack Server (`server.py`) handling REST API routes.
- **Database Layer**: SQLite3 (`chartora.db`) for development; PostgreSQL for production.
- **Authentication**: Ephemeral session tokens stored in `HttpOnly`, `Secure`, `SameSite=Lax` cookies.
- **Billing Engine**: Stripe Checkout + Customer Portal + Idempotent Webhook Listener (`/api/stripe/webhook`).
- **PWA Capabilities**: Service Worker (`public/sw.js`), Web App Manifest (`public/manifest.json`), fixed mobile bottom navigation bar.
